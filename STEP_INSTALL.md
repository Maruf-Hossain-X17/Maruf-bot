🛠️ STEP-BY-STEP INSTALLATION

1. Prepare Your Environment

Choose a compatible environment:

- Android with Termux
- Linux VPS
- Windows with a supported terminal
- macOS
- Compatible cloud development platform

Install a compatible Node.js version according to the project's "package.json" and documentation.

Official Node.js website:

https://nodejs.org/en/download/

---

2. Open the Project

Open the official Maruf Bot repository:

👉 https://github.com/maruf127679-pixel/Maruf-bot

Read the project documentation before installation.

For the original GoatBot project and its documentation, see the appropriate upstream repository and license information.

---

3. Clone the Repository

Open your terminal and clone the repository:

git clone https://github.com/maruf127679-pixel/Maruf-bot

Enter the project directory:

cd Maruf-bot

«If you are using a different installation method, follow the directory structure and instructions provided by that environment.»

---

4. Install Dependencies

Run the following command inside the project directory:

npm install

Wait for the installation to finish.

If npm reports an error, check:

- Node.js version
- npm version
- Internet connection
- Project documentation
- Native package requirements

Do not delete or replace project files without checking the error first.

---

5. Configure the Bot

Before starting the bot, review the configuration files included in the repository.

Common configuration areas may include:

- Bot settings
- Language selection
- Command configuration
- Database settings
- API integrations
- Dashboard settings
- Environment variables

Never publish passwords, access tokens, session data, or private API credentials on GitHub.

For configuration details, see:

👉 "Project Documentation" (https://github.com/maruf127679-pixel/Maruf-bot/blob/main/DOCS.md)

---

6. Account & Authentication Safety

This project relies on an unofficial Facebook API.

Keep in mind:

- Use an account and environment that you are authorized to use.
- Protect any authentication data.
- Do not share session cookies or login credentials.
- Do not upload private authentication files to a public repository.
- Review the platform's current rules before using automation.

Authentication methods can change over time. Use only the method documented for the current version of the project.

---

7. Google API Configuration

Some bot features may require Google services or API credentials.

If the current project requires Google Drive or OAuth integration:

1. Open the official Google Cloud Console.
2. Create or select a project.
3. Enable the required API.
4. Configure the appropriate OAuth consent screen.
5. Create credentials according to Google's documentation.
6. Store credentials securely using the project's supported configuration method.

Official resources:

- Google Cloud Console: https://console.cloud.google.com/
- Google OAuth documentation: https://developers.google.com/identity/protocols/oauth2
- Google Drive API documentation: https://developers.google.com/drive/api/guides/about-sdk

«Security: Never publish Client Secrets, refresh tokens, or other private credentials in a public GitHub repository.»

---

8. reCAPTCHA Configuration

If your dashboard includes a reCAPTCHA integration, configure it according to the current Google reCAPTCHA documentation.

Official website:

https://www.google.com/recaptcha/admin/create

Use the correct site configuration for your actual deployment domain. Do not copy an old domain setting blindly.

---

9. Start the Bot

Check the "package.json" file to find the correct start command.

For projects that define a "start" script, use:

npm start

If the project uses a different command, follow its documentation.

After startup, review the terminal output for errors.

---

10. Optional Uptime Monitoring

If your hosting provider allows monitoring, you can explore these services:

- Better Stack: https://betterstack.com/better-uptime
- UptimeRobot: https://uptimerobot.com/

Monitoring services do not guarantee that a sleeping, stopped, or crashed hosting service will remain online. Check the hosting provider's rules and limitations.

---

📌 COMMON PROBLEMS

❌ npm install fails

Check your Node.js version, npm version, network connection, and the error message.

❌ Bot does not start

Review the terminal logs, configuration files, and required environment variables.

❌ Dashboard does not open

Check the hosting port, deployment configuration, and whether the dashboard is included in the current source.

❌ API integration fails

Verify that the required API is enabled and that the credentials are configured securely.

❌ Authentication problems

Review the current project documentation and platform requirements. Never share private account credentials publicly.
